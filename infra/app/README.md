# Стенд DXA QC

Сервис контроля качества денситометрии для задачи 04 ЛЦТ 2026, развёрнутый на
https://ltz2026.ru/ без пароля. Трекер проекта на `/trac/` под паролем команды.

## Как устроено

- `dxaqc/io.py` читает DICOM с нестандартными UID, нечитаемые файлы помечает как Failure, схлопывает дубли по хешу пикселей.
- `dxaqc/analyze.py` определяет область и проверяет позвоночник правилами версии 0.1: ось, охват по подвздошным костям, яркие посторонние объекты. Бёдра пока только определяются по стороне.
- `dxaqc/render.py` рисует разметку поверх снимка.
- `dxaqc/pipeline.py` пишет `results.csv` и `results.xlsx` в формате раздела 2.5 ТЗ, архив разметки и `manifest.json`.
- `dxaqc/web/app.py` — FastAPI: страница прогонов и загрузки, таблица прогона, карточка снимка, `POST /api/batch`, `GET /api/runs/{id}`, `GET /api/health`, документация на `/docs`.

При старте контейнер сам прогоняет `Для теста.zip` организатора как прогон `example`.

## Деплой

```bash
infra/app/deploy.sh
```

Скрипт собирает образ, перезапускает контейнер `ltz_app` на `127.0.0.1:8098`, ждёт `/api/health` и
завершения прогона примера. Снаружи трафик идёт через nginx
`/etc/nginx/sites-available/ltz2026.ru` с basic-auth.

## Вопросы к Claude по рабочей папке

Зарегистрированные пользователи, которым админ выдал доступ, задают вопросы на `/ask`. Админка на `/admin`:
выдача доступа, лимит вопросов в сутки (по умолчанию 20), одобрение исполнения, журнал.

- Учётные записи и очередь вопросов — `dxaqc/web/accounts.py`, SQLite `/data/app.db` в volume `ltz_app_data`.
- Страницы и исполнитель — `dxaqc/web/ask.py`. Исполнитель передаёт вопросы брокеру с сервера, токен в браузер не попадает.
- Брокер — `tools/ask_broker.py`, отдельный инстанс Codellake `LTZ-ASK` (`~/.codellake/instances/LTZ-ASK/config.yaml`).
  Каждый вопрос идёт новой сессией. По умолчанию только чтение: команды, правка файлов, веб и подагенты запрещены.
  Полные права — только для вопроса, который одобрил админ.
- Рабочая папка — `/home/jk/exp/ltz2026-workspace`, копия проекта без `data/`, архивов и роликов:
  `tools/sync_workspace.sh`. Вопросы и прочитанные файлы уходят в Claude, медицинские данные туда не кладём.

Брокер работает на хосте в окне tmux `ltz-ask` и слушает шлюз сети контейнера `172.27.0.1:8099`, из интернета недоступен:

```bash
tmux new-window -d -t 0: -n ltz-ask "cd /home/jk/exp/LTZ2026/ltz2026 && tools/run_ask_broker.sh 2>&1 | tee -a /tmp/ltz-ask-broker.log"
```

Токен брокер создаёт при первом запуске в `~/.codellake/instances/LTZ-ASK/broker_token`. Контейнер работает от uid 10001,
поэтому ему монтируется копия, доступная только этому пользователю:

```bash
sudo install -d -m 755 /etc/ltz2026
sudo install -o 10001 -g 10001 -m 400 ~/.codellake/instances/LTZ-ASK/broker_token /etc/ltz2026/ask_token
```

Админа создаёт или сбрасывает ему пароль команда в контейнере, пароль печатается один раз:

```bash
docker exec ltz_app python -m dxaqc.web.accounts create-admin LOGIN
docker exec ltz_app python -m dxaqc.web.accounts set-password LOGIN
```

## Пакетная обработка без веба

```bash
python -m dxaqc.pipeline <папка_с_исследованиями> <папка_результатов>
curl -u ltz:*** -F "files=@study.zip" "https://ltz2026.ru/api/batch?wait=true"
```

## Ограничения версии 0.1

- Правила без обученной модели, пороги подобраны на обучающем наборе без отдельной проверочной выборки.
- Качество бёдер не оценивается, уровень Th12 не проверяется, детектор посторонних предметов слабый.
- Область определяется по ширине кадра GE Lunar Prodigy: 300 px позвоночник, 280 px бедро; для других аппаратов работает запасная эвристика симметрии.
- На стенде только обезличенные данные организатора. В финальной поставке сервис работает локально, без передачи снимков наружу.
