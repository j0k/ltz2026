# Kostik — дообучение на правках врачей и плагины

Kostik умеет дообучаться на новых снимках, **размеченных врачом**. Сами по себе новые снимки ничему не учат:
для обучения нужна метка человека — «качественный» или «есть нарушение» и какое именно. Такую метку врач ставит
в карточке снимка, в блоке «Управление снимком» (правка вердикта). Все правки накапливаются и становятся
обучающими данными.

Дообучение устроено как **система плагинов**. Каждый плагин отвечает за одну модель или набор порогов и проходит
один и тот же безопасный цикл.

## 1. Цикл дообучения

| шаг | что происходит |
|---|---|
| **collect** | собрать примеры: обучающий набор организатора + правки врачей из всех проверок; если врач поправил снимок из набора, берётся правка врача |
| **train** | обучить кандидата — новую версию модели или порогов |
| **evaluate** | честно оценить кандидата: кросс-валидация 5 фолдов по исследованиям, пороги подбираются только на обучающих фолдах |
| **accept** | ворота качества: кандидат не хуже действующей версии (допуск на шум 0,02) — иначе версия **не устанавливается** |
| **install** | установить новую версию; прежние версии хранятся, откат — одной кнопкой или командой |

Сервис подхватывает установленную версию сразу, без перезапуска и пересборки: модель бедра и пороги читаются
с учётом активной версии.

## 2. Встроенные плагины

| плагин | что обучает | ворота качества | где работает |
|---|---|---|---|
| `hip_trees` — модель бедра | ExtraTrees по 47 признакам формы, три классификатора: брак, укладка, поля ROI | ROC-AUC брака бедра по кросс-валидации | стенд и контейнер (нужен scikit-learn, он есть в образе) |
| `spine_thresholds` — пороги позвоночника | контраст постороннего предмета и яркость подвздошных костей (охват) | средний F1 двух критериев по кросс-валидации | везде, включая приложение для компьютера |

**Допуск наклона оси 5° задан ТЗ — плагин его не меняет.**

Минимум правок для запуска: 5 бёдер для `hip_trees`, 3 поясницы для `spine_thresholds`. Меньше — запуск
не нужен (можно принудительно).

## 3. Как пользоваться

### В пульте (администратор)

Страница **«Пульт» → «Дообучение на правках врачей»**:

- таблица плагинов: сколько правок накоплено, какая версия активна, её качество;
- **«Дообучить»** — полный цикл с установкой, если кандидат прошёл ворота качества;
- **«Пробный запуск»** — обучить и оценить, ничего не устанавливая;
- **«Откатить»** — вернуть предыдущую версию плагина;
- журнал всех запусков: кто, когда, итог, метрики кандидата и действующей версии.

### Из командной строки

```bash
python -m dxaqc.learning status                          # плагины, правки, активные версии, журнал
python -m dxaqc.learning feedback                        # правки врачей, которые пойдут в обучение
python -m dxaqc.learning run                             # дообучить все плагины
python -m dxaqc.learning run --plugin hip_trees --dry-run
python -m dxaqc.learning run --force                     # даже если правок меньше минимума
python -m dxaqc.learning rollback spine_thresholds       # откат к предыдущей версии
```

В контейнере стенда: `docker exec ltz_app python -m dxaqc.learning status`.

Переменные окружения: `DXAQC_DATA` — папка проверок и версий (по умолчанию `/data`),
`DXAQC_DATASETS` — обучающий набор организатора, `DXAQC_PLUGINS` — папка сторонних плагинов
(по умолчанию `<DXAQC_DATA>/plugins`).

### Где лежат версии

```
<DXAQC_DATA>/learning/
  history.jsonl                      журнал запусков
  hip_trees/active.json              активная версия (путь к весам и метрики)
  hip_trees/versions/<время>/        веса hip_trees.npz и info.json
  spine_thresholds/active.json
  spine_thresholds/versions/<время>/ params.json и info.json
```

## 4. Свой плагин

Положите файл `*.py` в папку плагинов — он подключится при следующем запуске. Минимальный плагин:

```python
from dxaqc.learning import Learner, register

@register
class MyPlugin(Learner):
    name = "my_plugin"                 # уникальное имя
    title = "Мой плагин"
    regions = ("lumbar_spine",)        # какие правки врачей ему нужны
    min_feedback = 3

    def train(self, samples):          # samples: Sample(key, sha, study, region, bad, types, pixels, source)
        ...                            # вернуть кандидата — любой объект
    def evaluate(self, cand, samples):
        return {"score": ...}          # score — одно число для ворот качества, больше — лучше
    def install(self, cand, metrics, version_dir):
        ...                            # сохранить кандидата в version_dir, вернуть путь к файлу
```

Необязательно: `available()` — проверить зависимости, `baseline()` — метрики действующей версии
(по умолчанию берутся из установленной версии), `accept()` — свои ворота качества, `collect()` — свой отбор
примеров. Ошибка в стороннем плагине не мешает остальным: она попадает в статус.

## 5. Ограничения и честные оговорки

- Качество растёт от **количества и разнообразия** правок: единичные правки обычно не проходят ворота качества,
  и это правильно — сервис не ухудшает модель ради одного случая.
- Правки врачей считаются истиной. Спорные случаи лучше обсуждать до правки: в пульте есть комментарий к правке.
- Исключённые из проверки снимки в обучение не идут.
- Проверено тестами [`tests/test_learning.py`](../tests/test_learning.py) и прогоном на обучающем наборе организатора (152 бедра, 101 поясница,
  около 40 секунд на двух ядрах).
