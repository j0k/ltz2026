# DXA QC — контроль качества денситометрии

**ЛЦТ 2026, задача 04 Департамента здравоохранения Москвы.** Сервис проверяет снимки денситометрии (DXA) поясничного
отдела и бедра в формате DICOM: определяет область, выносит вердикт о качестве, называет нарушение укладки
и объясняет его текстом, голосом и разметкой в стиле анатомического атласа. Работает локально —
снимки не покидают контур медорганизации.

через Codellake.

## Что делает

На входе — zip-архив или набор файлов DICOM. На выходе по каждому снимку:

- **область** — поясничный отдел, правое или левое бедро;
- **класс качества** — 0 (качественный), 1 (с нарушением) или пусто (не оценено);
- **тип нарушения** — охват, наклон оси, посторонние предметы; для бедра — укладка и поля вокруг зоны интереса;
- **объяснение** — что не так и почему, плюс атлас: зоны, ось, ориентиры поверх снимка.

Таблица результатов — по разделу 2.5 ТЗ (`results.csv` и `results.xlsx`), колонки:
`path_to_study, study_uid, image_uid, anatomical_region, quality_class, violation_type, processing_status, time_of_processing`.

## Честное состояние — версия 0.5.4

Позвоночник проверяется правилами, бедро — обученной моделью ExtraTrees. Против экспертной разметки на 99 исследованиях позвоночника
(в скобках — кросс-валидация 5×50 с 95% интервалом, пороги подбираются только на обучающей части):

| критерий | F1 | F1 по кросс-валидации | ROC-AUC |
|---|---|---|---|
| итог | 0,62 | 0,58 [0,46–0,74] | 0,75 |
| посторонние предметы | 0,62 | 0,55 | 0,85 |
| охват | 0,77 | 0,69 | 0,88 |
| наклон оси | 0,33 | 0,30 | 0,75 |

Бедро (150 размеченных снимков) — модель ExtraTrees по 47 признакам формы кости, краёв кадра и ориентиров атласа,
кросс-валидация по исследованиям: брак бедра ROC-AUC 0,66 [0,62–0,69], F1 0,47; укладка ROC-AUC 0,62; поля вокруг зоны
интереса ROC-AUC 0,80 (всего 7 примеров). Это слабее позвоночника: для бедра вердикт — подсказка для проверки.
Обучение — `scripts/train_hip.py` (scikit-learn), веса — `dxaqc/models/hip_trees.npz`, предсказание на numpy.

Разметки позвонков и зон от аппарата или врача в данных нет, поэтому анатомию сервис размечает сам. План — в
[роудмапе](https://ltz2026.ru/tz/roadmap.html), все нарушения с примерами — в
[каталоге](https://ltz2026.ru/tz/violations.html).

## Что есть на стенде

- загрузка своих файлов и прогон наборов организатора без загрузки, живой прогресс, отмена и очередь;
- карточка снимка: атлас со слоями и лупой, вердикт, пояснения текстом и голосом (Piper, Whisper — локально);
- страница прогона с инфографикой и сравнением с экспертами; пульт анализа — параметры, перезапуск, правка вердикта;
- принудительный анализ отклонённых файлов и анализ снимка через Claude — только с одобрения админа;
- API пакетной обработки, MCP-сервер для ИИ-ассистентов (токены выдают админы), Telegram-бот @QuJump_bot;
- админка: пользователи и инвайты, одобрения, журнал, мониторинг памяти и диска сервера.

## Запуск на чистой машине

Нужны Linux и Docker 20+. Интернет нужен только для сборки, дальше всё работает без сети: пакетный прогон
запускается с `--network none`, снимки не покидают машину.

```bash
./build.sh                               # образ dxaqc:<версия>, ~2 ГБ, 2 минуты
./run.sh <папка или архив.zip> <выход>   # пакетная проверка
./serve.sh                               # веб-интерфейс и API на http://localhost:8000, ./serve.sh stop — остановить
```

`run.sh` принимает папку с DICOM любой вложенности (zip внутри папки тоже распаковываются) или один zip-архив.
Исходные данные монтируются только на чтение. В выходной папке:

- `results.csv` и `results.xlsx` — строка на снимок в формате ТЗ 2.5, `path_to_study` относительно входа;
- `overlays.zip` — снимки с разметкой: позвонки, ось, границы зон, найденные предметы;
- `manifest.json` — сводка прогона, параметры, версия; PNG-слои рядом — для веб-интерфейса.

Параметры правил передаются флагами, список — `./run.sh --help`, например `--axis-limit-deg 5`.
Проверено на обучающем наборе организатора (252 снимка, 100 исследований): 90 секунд на весь набор, не больше
0,7 с на снимок, 252 из 252 обработаны без ошибок, два прогона дают побайтно одинаковые таблицы и разметку.

Стенд собирается и перезапускается одной командой `infra/app/deploy.sh`. Пакетная обработка через HTTP API —
ответ приходит после обработки, со ссылками на таблицы и архив разметки:

```bash
curl -F "files=@study.zip" "http://localhost:8000/api/batch?wait=true"
```

Разработка и тесты:

```bash
python3 -m venv .venv && .venv/bin/pip install -r infra/app/requirements.txt pytest
.venv/bin/python -m pytest -q tests
```

## Приложение для компьютера

Та же проверка локально, без интернета: окно приложения, дашборд, 3D, пояснения графом, офлайн-справка, пульт порогов,
локальный MCP-сервер для ИИ-ассистентов. Скачать — https://ltz2026.ru/download:

| система | файл |
|---|---|
| Windows 10/11, для пользователя | `DXAQC-<версия>-setup.exe` |
| Windows, на компьютер (тихо: `msiexec /i … /qn`) | `DXAQC-<версия>.msi` |
| Ubuntu 22.04/24.04, Debian 12 | `dxaqc_<версия>_amd64.deb` |

Код приложения — `dxaqc/desktop/` и `dxaqc/web/desktop.py` (режим `DXAQC_MODE=desktop`). Сборка на Linux:

```bash
packaging/build_windows.sh     # .exe (NSIS) и .msi (wixl): переносимый Python 3.12 + библиотеки win_amd64
packaging/build_deb.sh         # .deb: библиотеки под Python 3.10–3.12, окно WebKitGTK
packaging/publish.sh           # SHA256SUMS, latest.json, каталог моделей для сайта
python -m dxaqc.desktop --selftest   # самопроверка: анализ фантома, сервер, страницы, MCP
```

Проверка на настоящей Windows — `.github/workflows/desktop.yml` (вручную или по тегу `v*`).

## Данные

Данные организатора — медицинские, **в репозиторий не входят**: `data/`, архивы, модели и собранные документы
лежат рядом с репозиторием и подключаются к контейнеру томами (`infra/app/docker-compose.yml`). Тесты, которым
нужны эти данные, без них пропускаются. Что именно дал организатор — на странице
[«Данные задачи 04»](https://ltz2026.ru/tz/data.html).

## Устройство

```
dxaqc/
  io.py         чтение DICOM, отказы с причиной, дубли
  analyze.py    область, позвоночник (ось, охват, артефакты), бедро
  atlas.py      разметка в стиле анатомического атласа, слои
  pipeline.py   прогон набора, таблица результатов, сравнение с экспертами
  datasets.py   наборы организатора
  params.py     параметры анализа для пульта
  web/          веб-стенд на FastAPI: страницы, API, MCP, Telegram-бот, админка
infra/app/      образ, compose и скрипт деплоя стенда
infra/trac/     трекер проекта
tests/          pytest: пайплайн, веб, бот, MCP, страницы
tools/          трекер из командной строки, брокер вопросов к Claude
scripts/        e2e-проверки в браузере, сборка документов
```

В репозитории также лежат материалы первых дней: `tunnelguard/` — прототип по задаче 05 (не выбран,
см. [его README](tunnelguard/README.md)), `crew_*.py`, `infographic.py`, `web/`, `results/`.
