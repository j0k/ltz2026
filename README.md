# Kostik — контроль качества денситометрии

**[ЛЦТ 2026](https://i.moscow/lct), задача 04 Департамента здравоохранения Москвы.** Сервис проверяет снимки денситометрии (DXA) поясничного
отдела и бедра в формате DICOM: определяет область, выносит вердикт о качестве, называет нарушение укладки
и объясняет его текстом, голосом и разметкой в стиле анатомического атласа. Работает локально —
снимки не покидают контур медорганизации.

**Команда «Квантовый Скачок»:** Юрий Коноплёв, Алексей Чуркин. Разработка — вместе с ИИ-агентом Claude.

## Что делает

На входе — zip-архив или набор файлов DICOM. На выходе по каждому снимку:

- **область** — поясничный отдел, правое или левое бедро;
- **класс качества** — 0 (качественный), 1 (с нарушением) или пусто (не оценено);
- **тип нарушения** — охват, наклон оси, посторонние предметы; для бедра — укладка и поля вокруг зоны интереса;
- **объяснение** — что не так и почему, плюс атлас: зоны, ось, ориентиры поверх снимка.

Таблица результатов — по разделу 2.5 ТЗ (`results.csv` и `results.xlsx`), колонки:
`path_to_study, study_uid, image_uid, anatomical_region, quality_class, violation_type, processing_status, time_of_processing`.

## Честное состояние — версия 0.5.4

Позвоночник проверяется правилами, бедро — обученной моделью ExtraTrees. Против экспертной разметки на 99 исследованиях позвоночника
(в скобках — кросс-валидация 5×50 с 95% интервалом, пороги подбираются только на обучающей части):

| критерий | F1 | F1 по кросс-валидации | ROC-AUC |
|---|---|---|---|
| итог | 0,62 | 0,58 [0,46–0,74] | 0,75 |
| посторонние предметы | 0,62 | 0,55 | 0,85 |
| охват | 0,77 | 0,69 | 0,88 |
| наклон оси | 0,33 | 0,30 | 0,75 |

Бедро (150 размеченных снимков) — модель ExtraTrees по 47 признакам формы кости, краёв кадра и ориентиров атласа,
кросс-валидация по исследованиям: брак бедра ROC-AUC 0,66 [0,62–0,69], F1 0,47; укладка ROC-AUC 0,62; поля вокруг зоны
интереса ROC-AUC 0,80 (всего 7 примеров). Это слабее позвоночника: для бедра вердикт — подсказка для проверки.
Обучение — [`scripts/train_hip.py`](scripts/train_hip.py) (scikit-learn), веса — [`dxaqc/models/hip_trees.npz`](dxaqc/models/hip_trees.npz), предсказание на numpy.

Разметки позвонков и зон от аппарата или врача в данных нет, поэтому анатомию сервис размечает сам. План — в
[роудмапе](https://ltz2026.ru/tz/roadmap.html), все нарушения с примерами — в
[каталоге](https://ltz2026.ru/tz/violations.html).

## Что есть на стенде

- загрузка своих файлов и прогон наборов организатора без загрузки, живой прогресс, отмена и очередь;
- карточка снимка: атлас со слоями и лупой, вердикт, пояснения текстом и голосом (Piper, Whisper — локально);
- отклонённая картинка (JPG, скриншот, КТ/МРТ) получает описание: что за снимок и проекция (в том числе вид сбоку
  и КТ/МРТ), а отдельным списком — всё, что на ней кроме снимка: заголовки, водяные знаки, служебные надписи
  программы просмотра с прочитанным текстом, цветные метки, чёрные поля. Текст читает RapidOCR с кириллической
  моделью PaddlePaddle PP-OCRv5 (Apache 2.0) — локально, модель скачивается при сборке образа;
- страница прогона с инфографикой и сравнением с экспертами; пульт анализа — параметры, перезапуск, правка вердикта;
- принудительный анализ отклонённых файлов и анализ снимка через Claude — только с одобрения админа;
- API пакетной обработки, MCP-сервер для ИИ-ассистентов (токены выдают админы), Telegram-бот @QuJump_bot;
- админка: пользователи и инвайты, одобрения, журнал, мониторинг памяти и диска сервера.

## Запуск на чистой машине

Нужны Linux и Docker 20+; интернет — только для сборки, дальше без сети. Кратко:

```bash
./build.sh                               # образ dxaqc:<версия>
./run.sh <папка или архив.zip> <выход>   # пакетная проверка → results.csv, results.xlsx, overlays.zip
./serve.sh                               # веб-интерфейс и API на http://localhost:8000
```

Всё остальное — выходные файлы, параметры, API, разработка и тесты, системные требования и зависимости —
в отдельном файле **[docs/CLEAN_MACHINE.md](docs/CLEAN_MACHINE.md)**.

## Формат входных и выходных данных

**Вход:** папка с DICOM любой вложенности или zip-архив (вложенные zip распаковываются до 3 уровней).
Поддерживаются несжатые и сжатые DICOM (JPEG Baseline и Lossless, JPEG-LS, JPEG 2000, RLE, deflate),
8 и 16 бит, MONOCHROME1 и MONOCHROME2. Теги области (`BodyPartExamined`) и размера пикселя не нужны: область
определяется по изображению. Персональные данные не используются. Точные копии снимка внутри исследования
схлопываются.

**Выход** (`results.csv`, `results.xlsx`, строка на снимок, п. 2.5 ТЗ):

| колонка | формат | значения |
|---|---|---|
| `path_to_study` | строка | путь к файлу относительно входа |
| `study_uid`, `image_uid` | строка | StudyInstanceUID и SOPInstanceUID из DICOM |
| `anatomical_region` | строка | `lumbar_spine`, `hip_left`, `hip_right`, `unknown` (файл не прочитан) |
| `quality_class` | целое | `0` — качественный, `1` — есть нарушение, пусто — не оценено или не прочитан |
| `violation_type` | строка | коды через `;`: `coverage`, `axis_tilt`, `artifact`, `hip_positioning`, `hip_roi`; `none`; `error: <причина>` |
| `processing_status` | строка | `Success` / `Failure` |
| `time_of_processing` | число | секунды на снимок |

Дополнительно: `overlays.zip` — снимки с разметкой (позвонки Th12–L5, ось, границы зон, найденные предметы,
ориентиры бедра), `manifest.json` — сводка прогона, параметры, пояснения и измерения по каждому снимку.

## API

Веб-сервис ([`./serve.sh`](serve.sh), http://localhost:8000) — интерактивное описание на `/docs` (OpenAPI).

| метод | путь | что делает |
|---|---|---|
| `POST` | `/api/batch?wait=true` | пакетная обработка: поле `files` — zip или набор DICOM; с `wait=true` ответ после обработки: `run_id`, `state`, `summary`, `rows`, ссылки на таблицы и архив |
| `GET` | `/api/runs/{run_id}` | результат проверки (`?pretty=true` — с отступами) |
| `GET` | `/api/runs/{run_id}/progress` | ход проверки: этап, прогресс, позиция в очереди |
| `GET` | `/api/runs/{run_id}/events` | тот же ход потоком событий (Server-Sent Events) |
| `GET` | `/runs/{run_id}/files/{имя}` | файлы результата: `results.csv`, `results.xlsx`, `overlays.zip`, `manifest.json` |
| `GET` | `/api/health` | `{"status": "ok", "version": …}` |
| `POST` | `/mcp` | MCP-сервер для ИИ-ассистентов (Streamable HTTP, токен выдаёт администратор) |

```bash
curl -F "files=@study.zip" "http://localhost:8000/api/batch?wait=true"
curl "http://localhost:8000/api/runs/<run_id>?pretty=true"
```

## Модель, предобработка и постобработка

**Предобработка.** Сначала читается только заголовок: DICOM другой модальности (КТ, МРТ, УЗИ …), цветные,
однобитные маски и служебные скриншоты без признаков денситометра отклоняются до распаковки пикселей. Пиксели →
оттенки серого 0–255 (для >8 бит — окно по 0,5–99,5 перцентилям, MONOCHROME1 инвертируется). Отчёт денситометра
(страница с таблицами) распознаётся, и из него вырезается сам снимок.

**Область.** Для GE Lunar — по ширине кадра (300 px — поясница, 280 px — бедро), иначе — по симметрии и яркому
столбу по центру. Сторона бедра — по положению таза относительно диафиза.

**Поясничный отдел — правила по ориентирам:** осевая линия столба и угол хорды между верхней и нижней третью
(наклон оси против 5°); яркость подвздошных костей в нижних углах (охват); контраст пятна вне полосы столба
относительно его окружения (посторонние предметы). Пороги подобраны кросс-валидацией.

**Бедро — ExtraTrees** (200 деревьев, веса классов) по 47 признакам формы: диафиз, большой и малый вертел,
шейка, таз, поля у краёв кадра; три классификатора — брак, укладка, поля ROI, пороги по F1 «вне фолда».
Инференс — numpy по выгруженным деревьям. Обучение — [TRAINING.md](doc/TRAINING.md).

**Постобработка.** `quality_class = 1`, если сработал хотя бы один критерий; `violation_type` перечисляет все
коды. Для каждого снимка — пояснение текстом и графом «измерение → норма → вердикт» и атлас. Симметричные
пятна вверху кадра помечаются как «посторонний предмет? или ребро».

## Известные ошибки и ограничения

| ситуация | как обрабатывается |
|---|---|
| файл не DICOM, пустой, повреждён | строка `Failure`, `error: <причина>`; пакет продолжается |
| DICOM другой модальности, цветной, маска, скриншот | `Failure` с причиной; `--force` — проверить принудительно с пометкой |
| сжатие, которое не разжимается | `Failure`: «пришлите тот же снимок без сжатия» |
| битый, пустой или запароленный zip | строка `Failure` по архиву, остальные файлы проверяются |
| отчёт денситометра вместо снимка | снимок вырезается, результат помечен «ориентировочный» |
| аппарат не GE Lunar | область определяется по изображению; пороги подобраны на GE Lunar — точность может быть ниже |
| сколиоз | изгиб позвоночника может быть принят за наклон оси |
| нижние рёбра или бюстгальтер вверху кадра | вердикт «посторонний предмет» с пометкой «или ребро — проверьте» |
| уровень Th12 | определяется приблизительно, отдельно не проверяется |
| поля 3 и 2 см вокруг ROI бедра | в DICOM нет размера пикселя — оцениваются моделью, а не в сантиметрах |
| бедро в целом | ROC-AUC 0,66 — вердикт по бедру подсказка, стоит проверить глазами |

Необработанных исключений нет: любая ошибка чтения или анализа одного файла превращается в строку `Failure`.

## Дообучение на правках врачей

Врач правит вердикт в карточке снимка — правка становится обучающими данными. Плагины дообучения (модель бедра,
пороги позвоночника, сторонние из папки плагинов) обучают новую версию, оценивают её кросс-валидацией по
исследованиям и устанавливают, только если она не хуже действующей; откат — одной кнопкой. Запуск — в пульте
(«Дообучение на правках врачей») или `python -m dxaqc.learning run`. Подробно — [doc/LEARNING.md](doc/LEARNING.md).

## Приложение для компьютера

Та же проверка локально, без интернета: окно приложения, дашборд, атлас и чистый снимок, пояснения графом, офлайн-справка, пульт порогов,
локальный MCP-сервер для ИИ-ассистентов. Скачать — https://ltz2026.ru/download:

| система | файл |
|---|---|
| Windows 10/11, для всех пользователей, по умолчанию `C:\Program Files\Kostik-1.0\` (запрос администратора) | `Kostik-<версия>-setup.exe` |
| Windows, на компьютер (тихо: `msiexec /i … /qn`), та же папка | `Kostik-<версия>.msi` |
| Ubuntu 22.04–26.04, Debian 12–13 | `kostik_<версия>_amd64.deb` |

Командная строка (`Kostik.exe` в Windows, `kostik` в Linux): `--help`, `--version`, `--author`, `--mcp` (настройка ИИ-ассистента),
`--verbose` (подробный журнал запуска всех компонентов, файл `dxaqc-verbose.log`), `--selftest`, `--browser`, `--no-window`, `--port`.
`Kostik.exe` — консольный запускатель, ярлыки идут через оконный `Kostik-app.exe`; исходник — [`packaging/windows/launcher/`](packaging/windows/launcher/).

Код приложения — [`dxaqc/desktop/`](dxaqc/desktop/) и [`dxaqc/web/desktop.py`](dxaqc/web/desktop.py) (режим `DXAQC_MODE=desktop`). Сборка на Linux:

```bash
packaging/build_windows.sh     # .exe (NSIS) и .msi (wixl): переносимый Python 3.12 + библиотеки win_amd64
packaging/build_deb.sh         # .deb: библиотеки под Python 3.10–3.14, окно WebKitGTK
packaging/publish.sh           # SHA256SUMS, latest.json, каталог моделей для сайта
python -m dxaqc.desktop --selftest   # самопроверка: анализ фантома, сервер, страницы, MCP
```

Проверка на настоящей Windows — [`.github/workflows/desktop.yml`](.github/workflows/desktop.yml) (вручную или по тегу `v*`).
