# Kostik — обучение и дообучение

Kostik использует два вида моделей:

| область | метод | что обучается | где хранится |
|---|---|---|---|
| поясничный отдел | правила по анатомическим ориентирам | пороги 4 параметров | [`dxaqc/params.py`](../dxaqc/params.py) (значения по умолчанию) |
| бедро | ExtraTrees, 47 признаков формы | деревья и пороги трёх классификаторов | [`dxaqc/models/hip_trees.npz`](../dxaqc/models/hip_trees.npz) |

Почему так: примеров брака позвоночника мало (охват — 6, ось — 10, предметы — 17 из 99), а критерии ТЗ
геометрические — правила устойчивее обучаемой модели и объяснимы («угол 7,2° при допуске 5°»). Для бедра
укладку трудно формализовать, поэтому модель; из шести сравнённых подходов (логистическая регрессия,
бустинг, каскадный лес, признаки ResNet-50, DINOv2 и RAD-DINO) лучшим оказался ExtraTrees.

## 1. Окружение

Сервису для работы scikit-learn не нужен: деревья выгружаются в numpy и применяются numpy-кодом
([`dxaqc/hipmodel.py`](../dxaqc/hipmodel.py)). Для обучения — отдельное окружение:

```bash
python3 -m venv ../.venv-ml
../.venv-ml/bin/pip install -r infra/app/requirements.txt scikit-learn==1.9.1
```

## 2. Данные

Набор организатора раскладывается так (папку указывает переменная `DXAQC_DATASETS`):

```
<наборы>/
  train/                 ← содержимое «Исследования» из НД_для_обучения.zip (папка на исследование)
  train_labels.csv       ← таблица меток, см. ниже
```

Таблица меток строится из разметки организатора (лист «Калибровка» файла `разметка.xlsx`):

```bash
.venv/bin/python scripts/make_labels.py <распакованный НД_для_обучения> <наборы>/train_labels.csv
```

Строка на исследование: оценки экспертов 0/1 — `sp_pos`, `sp_axis`, `sp_art` (позвоночник: укладка и охват,
ось, посторонние предметы), `rh_pos`, `rh_roi`, `lh_pos`, `lh_roi` (правое и левое бедро: позиционирование и
ротация, область интереса), итоги `sp_bad`, `rh_bad`, `lh_bad`, комментарий эксперта. Пустая ячейка — области
в исследовании нет.

**Особенности данных, которые учитывают все скрипты:**
- 499 файлов DICOM, но уникальных по пикселям снимков 252: копии схлопываются до любой оценки;
- метки даны на исследование и область, а не на файл — снимок получает метку своего исследования и области;
- разбиение — только по исследованиям, причём исследования с общими снимками попадают в одну группу
  (`dxaqc/quality.py: groups`) — иначе копия снимка оказалась бы и в обучении, и в проверке;
- пороги подбираются только на обучающей части фолда.

## 3. Позвоночник: подбор порогов и оценка

```bash
DXAQC_DATASETS=<наборы> .venv/bin/python scripts/evaluate.py --repeats 50 --out results/quality_cv.json
```

Печатает для итога и каждого критерия F1, чувствительность, специфичность и ROC-AUC «как есть» и по
кросс-валидации 5 фолдов × 50 повторов с 95 % доверительными интервалами (бутстреп по исследованиям), а также
медиану подобранных порогов. Новые значения по умолчанию переносятся в [`dxaqc/params.py`](../dxaqc/params.py).

## 4. Бедро: обучение модели

```bash
DXAQC_DATASETS=<наборы> ../.venv-ml/bin/python scripts/train_hip.py --reps 5 --out dxaqc/models/hip_trees.npz
```

Что делает скрипт:
1. читает снимки, определяет область и сторону, зеркалит левое бедро (таз всегда справа);
2. считает 47 признаков (`dxaqc/hipmodel.py: features`): положение и форма диафиза, большого и малого вертела,
   шейки, таза, поля у краёв кадра, профили яркости;
3. честная оценка: 5 фолдов по группам исследований × повторы, порог F1 внутри обучающей части;
4. рабочий порог — по вероятностям «вне фолда» на всём наборе;
5. обучает итоговые модели (брак, укладка, поля ROI) на всех размеченных бёдрах и выгружает деревья в npz вместе
   с метаданными: признаки, медианы для пропусков, пороги, метрики кросс-валидации;
6. сверяет предсказание numpy-кода с scikit-learn.

Гиперпараметры по умолчанию: 200 деревьев, `min_samples_leaf=3`, `max_features="sqrt"`,
`class_weight="balanced"` (дисбаланс: 41 брак на 150 бёдер). Переопределить для эксперимента —
`DXAQC_HIP_PARAMS='{"min_samples_leaf": 10}'`. Подбор по сетке — [`scripts/hip_tune.py`](../scripts/hip_tune.py).

## 5. Итоговая метрика и сравнение версий

Сводная фитнес-функция: `0,35·F1 + 0,35·ROC-AUC` по областям `+ 0,30·macro-F1` по типам нарушений
([`dxaqc/fitness.py`](../dxaqc/fitness.py), описание — [`FITNESS.md`](../FITNESS.md)). Вероятности «вне фолда» для неё —
`scripts/baseline_oof.py <out.csv>`. Новая версия принимается, только если фитнес не ниже прежнего с учётом
доверительного интервала.

Эксперименты, которые уже проводились и на что не стоит тратить время повторно: [`scripts/trees_eval.py`](../scripts/trees_eval.py)
(бустинг, каскадный лес, Viola–Jones), [`scripts/ml_embed.py`](../scripts/ml_embed.py) + [`scripts/ml_eval.py`](../scripts/ml_eval.py) (признаки нейросетей),
[`scripts/hip_raddino_combo.py`](../scripts/hip_raddino_combo.py) (признаки формы + RAD-DINO: +0,01 ROC-AUC в пределах интервала),
[`scripts/learning_curves.py`](../scripts/learning_curves.py) (кривые обучения).

## 6. Дообучение на новых данных

1. Добавьте исследования в `<наборы>/train/` и строки в `train_labels.csv` в том же формате
   (новый файл разметки — через [`scripts/make_labels.py`](../scripts/make_labels.py)).
2. Переобучите бедро (`train_hip.py`) и перепроверьте пороги позвоночника (`evaluate.py`).
3. Сравните фитнес и доверительные интервалы с прежней версией; прогоните тесты `pytest -q tests`.
4. Увеличьте версию в [`dxaqc/__init__.py`](../dxaqc/__init__.py), соберите образ [`./build.sh`](../build.sh) — новые веса попадут в него.

Источник новых меток в работе — правки вердикта врачами в пульте. Их сбор, переобучение с воротами качества,
установка версий и откат автоматизированы плагинами дообучения — см. [LEARNING.md](LEARNING.md).

**Что даст больше всего:** разметка малого вертела (виден / частично / не виден) на снимках бедра и масштаб
в миллиметрах для полей вокруг зоны интереса — в DICOM организатора его нет.
