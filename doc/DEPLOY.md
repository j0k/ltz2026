# Kostik — руководство по развёртыванию

## 1. Требования

| | минимум | рекомендуется |
|---|---|---|
| ОС | Linux x86_64 (Ubuntu 22.04+, Debian 12+ и др.) | — |
| Docker | 20.10+ | 24+ |
| процессор | 2 ядра | 4 ядра |
| память | 4 ГБ | 8 ГБ |
| диск | 3 ГБ под образ (2,3 ГБ) и результаты | 10 ГБ |
| видеокарта | не нужна | — |
| сеть | только на время сборки образа | — |

Замер на 2 ядрах и 4 ГБ: 0,31–0,34 с на снимок, 90 с на весь обучающий набор (252 снимка), пик памяти
процесса ~190 МБ. ТЗ допускает до 3 минут на исследование.

## 2. Сборка

```bash
git clone <репозиторий> kostik && cd kostik
./build.sh                    # образ dxaqc:<версия> и dxaqc:latest
```

При сборке из сети скачиваются:
- Python-пакеты с зафиксированными версиями ([`infra/app/requirements.txt`](../infra/app/requirements.txt) и строка OCR в [`infra/app/Dockerfile`](../infra/app/Dockerfile));
- модель голоса Piper `ru_RU-irina-medium` и Whisper small — для озвучки и голосовых вопросов в веб-интерфейсе;
- кириллическая модель распознавания текста PaddlePaddle PP-OCRv5 — по зафиксированной ревизии, с проверкой SHA-256.

Модели для проверки качества (правила позвоночника и веса модели бедра [`dxaqc/models/hip_trees.npz`](../dxaqc/models/hip_trees.npz)) лежат
в репозитории и в сети не нуждаются.

Сборка с нуля занимает 3–10 минут в зависимости от сети. Повторная сборка из кэша — секунды.

## 3. Пакетная обработка (основной режим проверки)

```bash
./run.sh <папка или архив.zip> <папка результатов> [параметры]
./run.sh --help               # список параметров
```

- Контейнер запускается с `--network none`: снимки не покидают машину.
- Вход монтируется только на чтение, результаты пишутся от имени запустившего пользователя.
- Принимается папка с DICOM любой вложенности или zip-архив; zip внутри папок и вложенные zip распаковываются.
- В папке результатов: `results.csv`, `results.xlsx` (п. 2.5 ТЗ), `overlays.zip` (снимки с разметкой),
  `manifest.json` (сводка, параметры, пояснения по каждому снимку).
- В конце печатается JSON-сводка: снимков, годных, с нарушениями, отказов, среднее время.

Параметры правил (значения по умолчанию подобраны кросс-валидацией на обучающем наборе):

| параметр | по умолчанию | смысл |
|---|---|---|
| `--axis-limit-deg` | 5 | допуск наклона оси, ° (по ТЗ) |
| `--iliac-min-brightness` | 4 | минимальная яркость подвздошных костей в нижних углах |
| `--artifact-contrast` | 55 | насколько пятно вне столба ярче окружения, чтобы считать его предметом |
| `--spine-band-half` | 45 | полуширина полосы самого позвоночника, px |
| `--force` | выкл. | проверять и файлы, не похожие на DXA (результат не гарантирован) |

**Воспроизводимость.** Повторный прогон на тех же данных даёт побайтно одинаковые таблицы и разметку, кроме
колонки времени.

## 4. Веб-интерфейс и HTTP API

```bash
./serve.sh                    # http://localhost:8000, данные — в томе dxaqc_data
PORT=8080 ./serve.sh          # другой порт
./serve.sh stop
```

Сервис слушает только `127.0.0.1`. Для доступа из сети поставьте перед ним обратный прокси (nginx) с TLS.
Описание API — README, раздел «API»; интерактивная документация — `http://localhost:8000/docs`.

## 5. Проверка после установки

```bash
curl -s http://localhost:8000/api/health            # {"status":"ok","version":"0.5.4"}
./run.sh "Для теста.zip" /tmp/out                    # 3 снимка: поясница, левое и правое бедро, 0 отказов
```

## 6. Стенд с доменом (как ltz2026.ru)

[`infra/app/docker-compose.yml`](../infra/app/docker-compose.yml) и [`infra/app/deploy.sh`](../infra/app/deploy.sh) — сборка и перезапуск одной командой, прогон примера
после запуска. Наборы организатора подключаются томом только на чтение (`DXAQC_DATASETS`), результаты — том
`/data`. Перед контейнером — nginx с TLS (Let's Encrypt), лимит загрузки 64 МБ.

Медицинские данные и материалы организатора в git не попадают (`.gitignore`: `*.dcm`, `*.zip`, `data/`).
Для стенда их готовят в отдельной папке (`DXAQC_DATASETS_DIR`, по умолчанию `/srv/ltz2026/datasets`)
и запускают контейнер из готового образа:

```bash
./serve.sh                                   # сам подключает наборы, если они разложены
# или через compose:
DXAQC_DATASETS_DIR=/srv/ltz2026/datasets sudo docker compose -f infra/app/docker-compose.stand.yml up -d
```

Состав папки: `train/` (100 исследований), `test/`, `labels_clean.csv`, `«Для теста.zip»` (сид-пример),
`tz/` (документы ТЗ для `/tz/`). Без набора `train/` на главной не будет блока «готовые примеры» и
галерея будет пустой — они строятся из прогона обучающего набора.

Переменные окружения образа:

| переменная | смысл |
|---|---|
| `DXAQC_DATA` | папка проверок и служебных данных (по умолчанию `/data`) |
| `DXAQC_DATASETS` | папка наборов организатора: `train/` (исследования), `train_labels.csv`, `test/` |
| `DXAQC_TTS_MODEL`, `DXAQC_STT_MODEL` | модели голоса |
| `DXAQC_OCR_MODEL` | модель чтения надписей на отклонённых картинках |

## 7. Приложение для компьютера

Готовые установщики — https://ltz2026.ru/download (`.exe`, `.msi`, `.deb`, суммы CRC32 и SHA-256, подпись GPG).
Сборка на Linux:

```bash
packaging/build_windows.sh "$PWD/../build-desktop" "$PWD/../dist"   # .exe (NSIS) и .msi (wixl)
packaging/build_deb.sh     "$PWD/../build-desktop" "$PWD/../dist"   # .deb, Python 3.10–3.14
packaging/publish.sh       "$PWD/../dist"                           # суммы, подпись, latest.json
```

Пути передавайте абсолютными. Установка `.deb`: `sudo apt install ./kostik_<версия>_amd64.deb`,
проверка — `kostik --selftest`.

## 8. Обновление и откат

- Обновление: `git pull && ./build.sh`; образы помечаются версией `dxaqc:<версия>`, прошлая версия остаётся.
- Откат: `DXAQC_IMAGE=dxaqc:<прошлая версия> ./run.sh …` (или [`./serve.sh`](../serve.sh)).
